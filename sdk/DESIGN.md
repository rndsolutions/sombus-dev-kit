# SOM Managed Bus SDKs: core design

**Status: draft, first slice.** One design for the TypeScript, Python, .NET and Java SDKs, so
they don't drift. TypeScript implements it first ([`typescript/`](typescript/)); the others
follow it without re-deciding anything. Language idioms can differ (async style, casing); concepts,
type names and behaviour can't.

Every section says what's **built** in this slice, and what's **designed** or **pending** (and on
what).

## 1. Principles

- **One behaviour, proven by one kit.** Every SDK runs the [conformance kit](conformance/) in CI.
  A behaviour that isn't in the kit isn't part of the contract.
- **The gateway is the oracle.** Kit expectations come from the bus's own verdicts, and the bus's
  CI checks the kit and this SDK against its gateway on every change.
- **Suite-versioned.** An SDK release states the suite it supports (`som-1.0.0+lib-0.2.2`). A SOM
  1.x or skill library change adds a suite; it doesn't change an old one.
- **No payloads in logs.** SDK events and errors carry identifiers (`message_id`, status, rule id),
  never message content, tokens or secrets.
- **Light.** HTTP and JSON from the platform. No runtime dependencies in the core; AWS SDKs only
  in the SigV4 and SQS adapters, as optional peer dependencies.
- **Claims rule.** SDK docs say "passes the som-bus checks for `som-1.0.0+lib-0.2.2`", never
  "certified" or "compliant". SOM defines no conformance tiers.

## 2. Modules

| Module | Does | Status |
|---|---|---|
| Models | Envelope and payload types, open enums | **Built** (envelope, handwritten); payload models designed (§3) |

| Dry run | Your workspace's `validate` route | Designed (§8) |
| Snapshot helper | Per-story sequence tracking, whole snapshots, single writer | Designed (§10) |
| Consumer | Receive loop over the HTTPS pull API; an SQS FIFO adapter for readers in AWS | Designed (§10); a reference loop is in [`examples/consumer/`](../examples/consumer/) |
| Skill interface, executor runtime | `evaluate(snapshot, config, context)`, consumer → skills → publisher | Pending: follows the executor contract |
| Testing helpers | Fixture player, test runs against a vendor workspace | Designed |

## 3. Models

- **Envelope** (`SomEnvelope`): every SOM 1.0 envelope field, `payload` generic.
  `system_type`, `message_type` and rule `source` are **open**: the 1.0 values are listed, and any
  other string is allowed, because a 1.x producer may send members 1.0 doesn't know and consumers
  must tolerate them.
- **Payloads**: generated per language from `upstream/som-1.0/schema/`, never handwritten:
  TypeScript `json-schema-to-typescript`, Python `datamodel-code-generator`, .NET `NJsonSchema`,
  Java `jsonschema2pojo`. Enums are generated as open (a known set plus a string fallback), so a
  1.x value parses. Generated code is committed and regenerated by a script pinned to the suite.
  Not in this slice: TypeScript payloads are `JsonObject` or the caller's own type.

## 4. Envelope builder

`buildEnvelope(input) → SomEnvelope` (Python `build_envelope`, .NET `Envelope.Build`, Java
`Envelope.builder()`).

| Field | Default | Rule |
|---|---|---|
| `som_version` | `1.0.0` | fixed per suite |
| `message_id` | new UUIDv7 | set only to rebuild a message already sent |
| `correlation_id` | new UUIDv7 | the story's; reuse it for every later message about the story |
| `causation_id` | absent | `buildFollowUp(cause, …)` sets it to the cause's `message_id` and copies its `correlation_id` |
| `timestamp` | now, UTC, `toISOString()` precision | an explicit value must be RFC 3339 **with** a zone |
| `topic` | `som.<message_type>` | must start with `som.` |
| `extensions` | absent | keys namespaced `com.<vendor>.*` |

The builder checks only what it sets or can check cheaply, and throws `EnvelopeError(field)`.
Schema validation is the validator's job (§8) and, finally, the gateway's.

**Idempotency lives in the message, not the transport.** Build once, keep the message (object or
serialised JSON) until the bus gives a final answer, and resend exactly that. Rebuilding for a
retry makes a new `message_id` (a second message) or, with the same id and a new timestamp,
`409 message_id.reused`.

## 5. Auth

`TokenProvider.getToken({ forceRefresh }) → string`. Implementations:

- **`ClientCredentials`** `{ tokenUrl, clientId, clientSecret, scope = "sombus/publish" }`.
  `POST tokenUrl`, `grant_type=client_credentials`, id and secret as HTTP Basic (form-encoded
  first, RFC 6749 §2.3.1). `tokenUrl` is the bus's token service, `/v1/oauth/token`; any
  OAuth 2.0 token endpoint works the same way.
  - Cache the token until `expires_in − min(60 s, lifetime / 2)`.
  - One fetch at a time: concurrent callers wait on the same request.
  - `TokenError { status, retryable, oauthError }`. A refusal (`invalid_client`, `invalid_scope`,
    other 4xx) is **not** retryable: it's configuration. Unreachable, 429 and 5xx are.
- **`StaticToken`**: a fixed bearer the caller manages, such as one from your own identity provider.
- **`SigV4`** (designed): for producers in AWS, posting to `/v1/tenants/{t}/iam/messages`. Lives in an adapter with
  the AWS SDK as an optional peer dependency.

## 6. Publisher and the error model

`SomBusClient { baseUrl, auth, publishPath = "jwt/messages", retry, onAttempt }`.
A workspace app sets `publishPath` to `tenants/{t}/messages`; the default is the route for apps
RND manages. `publish(message) → Verdict`. The body is serialised **once**; every attempt sends the same bytes.

The bus answers in one format (the API reference in the docs; edge rejections use it too). The SDK maps it to three verdicts:

| Answer | Verdict | Fields |
|---|---|---|
| `202 { accepted, message_id, message_type, family, tolerated? }` | `Accepted` | `messageId`, `messageType`, `family`, `tolerated[]` (warnings, not failures), `dryRun` |
| `200 { accepted, duplicate: true }` | `Duplicate` | `messageId`. Success: an earlier attempt got through |
| `4xx/5xx { accepted: false, violations[] }` | `Refused` | `status`, `source`, `rule`, `path` of the first violation; all `violations`; `retry` |
| anything else (API Gateway throttle, a proxy, HTML) | `Refused` | `source: transport`, `rule: http.<status>` |

`source` keeps "the standard says no" apart from "our policy says no": `schema` and `conformance`
(SOM 1.0), `sequence` (conformance §6, across messages), `policy` (this bus's rules),
`transport` (the SDK's own label for a non-gateway answer). Callers branch on `status` and `rule`,
never on `message`.

`publish` **resolves** with the bus's final answer, and **rejects** only when there is none:

| Outcome | How it surfaces | Caller does |
|---|---|---|
| Accepted, Duplicate | resolves | done |
| Refused, `retry: none` | resolves | don't resend this message: fix it, or rebuild from current state with a new `message_id` |
| Retries exhausted (429, 5xx, timeouts, network) | rejects `PublishError { messageId, attempts, last? }` | keep the message in an outbox; resend it later unchanged |
| Token endpoint refused the credentials | rejects `TokenError { retryable: false }` | configuration: alert |

Rule ids and what they mean are the gateway's: every rule has a page in the docs (Reference › Rules).

## 7. Retries

Per the docs (Producers › Retries):

| Answer | `retry` | SDK does |
|---|---|---|
| timeout, network error, no answer | – | back off, resend the same bytes |
| `408`, `429`, `5xx` (incl. `503 bus.publish_failed`) | `backoff` | back off, resend the same bytes; honour `Retry-After` |
| `401` | `refresh_token` | force a new token and resend **once**, with no delay. A second `401` is final |
| any other `4xx`, incl. every `409` | `none` | stop. `409 commit.contention` is retryable only with a **fresh snapshot**, which only the caller can build |
| token endpoint unreachable, 429, 5xx | – | counts as an attempt; back off |

Backoff before retry *n* (n ≥ 1): `min(maxDelay, baseDelay · 2^(n−1)) × (0.5 + 0.5·r)`, `r`
uniform in [0, 1). With `Retry-After`, `min(maxDelay, Retry-After)`. Defaults: 5 attempts,
`baseDelay` 500 ms, `maxDelay` 30 s, 10 s per attempt. Per-story ordering (hold a story's next
message while one is retrying) is the caller's, or the executor runtime's, not the publisher's.

`onAttempt({ message_id, attempt, status, outcome, rule?, delay_ms? })` fires once per attempt,
for logs and metrics. It never includes the payload or the token.

## 8. Validator and dry run

- **Offline validator** (designed, next slice): the pinned schema pack, JSON Schema 2020-12 with
  format assertion on, the pre-1.0 rule (conformance §3), payload chosen by `message_type` only,
  and the 1.x tolerance rule, with **the gateway's rule ids** (`<schema>.<keyword>`,
  `som_version.pre_1_0`). It passes `cases/validation.json`. It needs a JSON Schema library per
  language (TypeScript: `ajv` + `ajv-formats`), so it ships as its own entry point, and the
  publish path doesn't load it.
- **Dry run against the bus**: your workspace's `POST /v1/tenants/{t}/validate` takes the same
  token as publishing and answers as a publish would, with `dry_run: true`, and publishes nothing.
  The SDK's `validate(message) → Verdict` (designed) calls it and parses the answer with the same
  `parseVerdict`: `Accepted` with `dryRun: true`, or `Refused`.

## 9. Configuration and logging

Constructor options, no global state, no environment variables read by the SDK. Every I/O seam
(`fetch`, clock, random, sleep) is injectable, which is how the kit runs deterministically. The
SDK doesn't log; it emits `onAttempt` events and typed errors, and the caller logs them.

## 10. Consumer, snapshot helper, executor (outline)

- **Snapshot helper**: per-story state (last `sequence_number`, members, assets, terminal state)
  that builds the next **whole** snapshot and refuses locally what the gateway would refuse
  (`sequence_number.not_increasing`, `snapshot.members_missing`…). Single writer per story.
- **Consumer**: one interface, `receive() → Delivery[]`, `ack(delivery)`. An HTTPS pull adapter
  (client id and secret) and an SQS FIFO adapter (IAM). Per-story ordering; a pluggable `message_id` idempotency
  store; the highest `sequence_number` wins; unknown `message_type`s and extensions are ignored,
  not failed.
- **Skill interface and executor runtime**: pending; they follow the executor contract.

## 11. The conformance kit

`sdk/conformance/`, language-neutral JSON. Format in [conformance/README.md](conformance/README.md).

| File | Cases | Checks |
|---|---|---|
| `cases/validation.json` | the 18 published examples and the 20 negative cases from `upstream/som-1.0/examples` | accept + family, or reject + sources + rule ids |
| `cases/envelope.json` | builder inputs, a fixed clock | fields set, UUIDv7 prefix from the clock, errors by field |
| `cases/verdicts.json` | every status and rule id the bus answers with | verdict kind, source, rule, path, retry class |
| `cases/retry.json` | scripted answers to successive attempts | outcome, attempts, delays, same body, token fetches |

Next: consumer semantics (duplicate, late snapshot, unknown type, a 1.1.0 variant → end state),
token cache cases, and executor cases.

## 12. Names across languages

| Concept | TypeScript | Python | .NET | Java |
|---|---|---|---|---|
| Client | `SomBusClient` | `SomBusClient` | `SomBusClient` | `SomBusClient` |
| Publish | `publish()` | `publish()` (async) | `PublishAsync()` | `publish()` → `CompletableFuture` |
| Verdicts | `Accepted`, `Duplicate`, `Refused` (union on `kind`) | dataclasses | records | sealed interface + records |
| Retry class | `'backoff' \| 'refresh_token' \| 'none'` | `RetryClass` enum | `RetryClass` enum | `RetryClass` enum |
| Errors | `PublishError`, `TokenError`, `EnvelopeError` | same names | `…Exception` | `…Exception` |
| Auth | `ClientCredentials`, `StaticToken` | same | same | same |
| Builder | `buildEnvelope`, `buildFollowUp` | `build_envelope`, `build_follow_up` | `Envelope.Build`, `Envelope.FollowUp` | `Envelope.builder()`, `Envelope.followUp()` |

Wire field names stay snake_case in every language's serialised JSON.

## 13. Decisions

Decided:
- **Where the SDKs live**: here, in one public Apache 2.0 repository with a folder per language and
  the kit, so the kit and every runner change together and one CI proves they agree.
- **The dry-run route**: `validate` takes the same token as publishing and answers with the
  gateway's own status and body, so every SDK parses it with the code it already has.

Open:
1. **One package or two per language.** **Recommendation:** a core package (models, builder,
   validator, auth, publisher, consumer) and a separate executor package that depends on it,
   because the executor follows the skill library's versions and the core doesn't.
2. **Default retry numbers** (5 attempts, 0.5 s doubling to a 30 s cap, 10 s per attempt). Confirm,
   or set per environment.
3. **Package names**: the TypeScript package is `@rnd-solutions/sombus-sdk`, a placeholder until
   names are reserved on the registries.
